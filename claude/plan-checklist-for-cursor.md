## 1. Что делаем

Новый раздел **«Процесс: от топосъёмки до проекта»** — интерактивный чек-лист-трекер из **8 стадий**, ведущий новичка через реальный проект японского сада. Кандзи раздела: **道** уже занят «Рекомендациями» → используем **順** (порядок, последовательность) или **程** (тэй, «процесс/этап»). Предлагаю **順**.

Три ключевых свойства:

1. **Интерактивность**: чекбоксы по каждому пункту, прогресс-бары (по стадии и общий), сворачивание/разворачивание стадий.
2. **Заметки**: текстовое поле к **каждому пункту** (авторасширяющийся textarea), где пользователь пишет свои наблюдения по конкретному участку.
3. **Персистентность**: всё состояние (галочки, заметки, свёрнутость стадий) сохраняется в `localStorage` и переживает перезагрузку. Ключ: `garden-process-tracker-v1`.

Аудитория — новичок: у каждого пункта, кроме названия, есть **пояснение «зачем»** (1–2 предложения) и **ссылка на урок курса**, где тема разобрана.

Archicad/Enscape в этой версии НЕ вплетаем в пункты (позже будет отдельный шаблон Archicad, тогда добавим ветку «в модели»). Исключение — стадия 8, она по природе про визуализацию.

## 3. Модель данных (`data/process.ts`)

```ts
export type ProcessItemDef = {
  id: string;            // стабильный, напр. "1-topo" — НЕ менять после релиза, к нему привязан localStorage
  title: string;         // короткое название пункта
  why: string;           // пояснение для новичка: зачем этот шаг
  lessonHref?: string;   // ссылка на урок/раздел курса, напр. "/module-1#l1-3"
  lessonLabel?: string;  // подпись ссылки, напр. "Урок 1.3 · Планировка"
};

export type ProcessStageDef = {
  id: string;            // "s1".."s8"
  kanji: string;         // кандзи стадии
  phase: "data" | "idea" | "body" | "show";  // фаза для цветовой маркировки
  title: string;
  intro: string;         // 1–2 предложения: суть стадии и почему она на этом месте
  gate: string;          // «ворота»: условие, без которого нельзя переходить дальше
  items: ProcessItemDef[];
};
```

Состояние пользователя (localStorage):

```ts
type TrackerState = {
  version: 1;
  checked: Record<string, boolean>;   // itemId -> done
  notes: Record<string, string>;      // itemId -> текст заметки
  collapsed: Record<string, boolean>; // stageId -> свёрнута ли
};
```

## 4. Контент: 8 стадий (полные данные для `data/process.ts`)

Фазы и цвета: **сбор данных** (стадии 1–2, нейтральный `--stone`), **замысел** (3–4, `--pine`), **тело сада** (5–6, `--moss` или тот же `--pine` темнее), **подача** (7–8, `--shu`). Цвет — тонкая полоса слева у карточки стадии, как у `.note`.

### Стадия 1 · 測 · Обследование участка
**Фаза**: сбор данных.
**Intro**: Сад начинается не с эскиза, а с фактов. Всё, что вы здесь пропустите, вернётся переделками: не туда посаженный клён сгорит, пруд соберёт весь сток соседа. На этой стадии запрещено придумывать — только фиксировать.
**Gate (ворота)**: есть топосъёмка + фотопанорама 360° + заполненная таблица условий. Без этого не открывается стадия 2.

Пункты:

1. **Топосъёмка / геодезия** — why: «Горизонтали рельефа — это будущая композиция: где холм миэгакурэ, куда стечёт вода. Заказать геодезисту или снять самим (для малого участка достаточно нивелира и сетки 3×3 м)». lessonHref: урок 6.1 (рельеф).
2. **Границы, кадастр, охранные зоны коммуникаций** — why: «Кабель или газовая труба под будущим прудом = перенос пруда. Проверить до концепции, а не после».
3. **Инсоляция: карта солнца/тени по сезонам** — why: «Мох живёт в тени, сосна — на солнце. Снять тени утром/днём/вечером, помнить о низком зимнем солнце». lessonHref: урок 4.3 (мох).
4. **Почва: pH, механический состав, плодородный слой** — why: «Кислая почва региона — союзник (мох, рододендроны). pH-тест в 5–6 точках; глина = вопросы к дренажу». lessonHref: раздел «Палитра севера».
5. **Вода: УГВ, сток, снеговые мешки** — why: «Куда уходит талая вода — туда просится пруд или сухой ручей. Высокий УГВ меняет конструкцию водоёма».
6. **Ветер: роза ветров и коридоры** — why: «Клён ложнозибольдов не переживёт ветровой коридор; фоновые ели — переживут. Ветрозащита определяет, где будут акценты». lessonHref: урок 4.1.
7. **Инвентаризация существующего: деревья, валуны, перепады** — why: «Взрослая сосна — готовое ниваки за 30 лет форы; ледниковый валун — бесплатный исигуми. Пометить всё ценное на съёмке». lessonHref: практикум «Участок в лесу».
8. **Фотофиксация: панорамы с будущих окон и углов** — why: «Снимать с высоты глаз с точек, где будут окна и терраса — это заготовки будущих видовых точек».
9. **Климат: зона зимостойкости, снеговая нагрузка** — why: «Зона 3b–4 отсекает половину «японского» ассортимента заранее — и это хорошо: меньше соблазнов». lessonHref: «Палитра севера».

### Стадия 2 · 観 · Анализ
**Фаза**: сбор данных.
**Intro**: Данные собраны — теперь их надо прочитать. Анализ отвечает на три вопроса: что за участок нам достался (диагноз по типологии), что вокруг него (сяккэй или помойка соседа) и чего хочет заказчик на самом деле.
**Gate**: сформулирован диагноз участка одним предложением + карта видов + бриф заказчика подписан.

Пункты:

1. **Карта видов: что видно за границей участка** — why: «Обойти участок по периметру и с каждой стороны записать: заимствовать (лес, гора — сяккэй) или скрывать (забор, гараж). Это дешевле всего решить сейчас». lessonHref: урок 1.3 (сяккэй).
2. **Диагноз по типологии практикума** — why: «Определить свой случай из восьми: плоский малый, склон вверх/вниз, пенал, тенистый двор, лес, парк, общественный. Диагноз = готовая стратегия». lessonHref: «Практикум: типовые участки».
3. **Бриф заказчика: сценарии жизни, а не «хотелки»** — why: «Спрашивать не „хотите ли пруд“, а „где вы пьёте утренний кофе, откуда смотрите на сад зимой“. Главная видовая точка почти всегда — окно, у которого человек реально живёт».
4. **Бюджетная рамка и очерёдность** — why: «Японский сад хорошо строится очередями: сначала скелет (рельеф+камни), потом наполнение. Честная рамка сейчас спасает от урезанного „всего понемногу“ потом». lessonHref: ошибка «уместить всё» в практикуме.
5. **Аудит шума и звука** — why: «Уединённость (столп 5) — это ещё и звук: где источники шума, чем маскировать (вода, сиси-одоси)». lessonHref: столп 5.
6. **Свод ограничений в один лист** — why: «Одна страница: рельеф, тени, ветер, вода, виды, бюджет. Это фильтр, через который пройдёт каждая идея следующей стадии».

### Стадия 3 · 演 · Режиссура
**Фаза**: замысел.
**Intro**: Самая японская стадия — и та, которую все пропускают. До плана и до дорожек назначаем: ЧТО зритель увидит, ОТКУДА и КОГДА. Сад проектируется как последовательность сцен; дорожки будут потом, как монтаж этих сцен.
**Gate**: паспорт видовых точек (3–5 для частного сада) + календарь любования по месяцам.

Пункты:

1. **Календарь любования по месяцам** — why: «Назначить саду сезонные пики: что цветёт в мае (ханами), что горит в октябре, что рисует снег (юкими). Красиво „вообще“ не бывает — бывает красиво в момент». lessonHref: урок 1.1.
2. **Паспорт видовых точек** — why: «Для каждой точки: откуда (окно, терраса, скамья), направление, передний план, главный объект, сезонный пик. Это скелет всего проекта и будущий список камер». lessonHref: урок 1.3 + практикум «парк» (паспорт камер).
3. **Одна главная сцена** — why: «У сада одна доминантная картина, остальные — подчинённые. Три равные доминанты = ни одной». lessonHref: практикум «плоский малый».
4. **Черновая раскадровка маршрута** — why: «Пронумеровать сцены в порядке показа: что открывается сразу, что прячется до поворота (миэгакурэ), где пауза. Пока стрелками на кальке поверх съёмки, без дорожек». lessonHref: deep-dive урока 1.3.
5. **Сверка режиссуры с брифом** — why: «Каждая сцена должна попадать в реальный сценарий жизни заказчика: сцена, которую никто не увидит по дороге на работу, — мёртвая».

### Стадия 4 · 構 · Концепция
**Фаза**: замысел.
**Intro**: Теперь замысел собирается в план. Выбираем тип сада, режем участок на зоны, трассируем маршрут между сценами — и прогоняем всё через фильтр шести столпов.
**Gate**: эскиз-концепция М1:100 (или 1:200), прошедшая проверку шести столпов; заказчик согласовал.

Пункты:

1. **Тип сада** — why: «Карэсансуй / чайный родзи / прогулочный с прудом / цубонива — тип определяется диагнозом участка и бюджетом, а не вкусом. Для севера сухой сад — самый надёжный». lessonHref: урок 2.3 (note «для России»).
2. **Зонирование: сцены → зоны, буферы, хоздвор** — why: «Хозяйственное (компост, сарай, парковка) выносится за кулисы — вечнозелёные экраны. Сад не должен видеть быт». lessonHref: столп 5.
3. **Трассировка маршрута по раскадровке** — why: «Дорожка — ломаная между видовыми точками, где каждый изгиб мотивирован: показывает, скрывает или тормозит. Изгиб без ответа — лишний». lessonHref: deep-dive урока 1.3.
4. **Границы: изгороди, кулисы, входной „шлюз“** — why: «Уединённость проектируется на плане: многослойная граница + декомпрессия входа (узко → поворот → раскрытие)». lessonHref: столп 5.
5. **Проверка шести столпов** — why: «Закрыть план рукой, открывать по фрагменту: каждый элемент объясним одним из шести принципов? Нет — кандидат на удаление». lessonHref: урок 1.2.
6. **Проверка масштаба (сюккэй)** — why: «Если на плане холм-„гора“ — всё рядом с ним в уменьшенном масштабе. Один элемент честного размера убивает иллюзию». lessonHref: столп 1.
7. **Сцены-коллажи по видовым точкам** — why: «Для 2–3 главных сцен — картинка поверх реального фото из точки (стадия 1): эскиз на планшете (Procreate / Morpholio Trace: фото нижним слоем, калька сверху) или генеративное редактирование фото (Photoshop Generative Fill, Krea, PromeAI — дорисовать камни/клён в выделенной области, геометрия кадра остаётся настоящей). Вариант с болванки: скриншот черновой 3D-сцены → sketch-to-render (Rendair, PromeAI, Veras). Каждый AI-результат проверять фильтром шести столпов — генератор их не знает и тянет клише (бамбук, красные мостики, зона 6)». lessonHref: урок 1.2 (столпы как фильтр).
8. **Согласование концепции с заказчиком** — why: «Согласовывать на эскизе дёшево, на смете — дорого. Показывать через сцены („вот что вы видите из кухни в октябре“) — коллажи из предыдущего пункта, а не план».

### Стадия 5 · 骨 · Скелет сада
**Фаза**: тело сада.
**Intro**: От бумаги к материи. Сначала — то, что нельзя будет передвинуть: рельеф, вода, камни. Растения подождут — они пересаживаются, камень стоит века.
**Gate**: рельеф, водоём/сухое русло и все группы камней зафиксированы на генплане с отметками; главные камни проверены с видовых точек.

Пункты:

1. **Баланс земляных масс** — why: «Грунт из пруда/котлована = холмы миэгакурэ. Считать заранее, чтобы не вывозить и не завозить». lessonHref: урок 6.1 + практикум «плоский малый».
2. **Рельеф: холмы, ложбины, перепады** — why: «Даже 40–60 см перепада на плоском участке создают глубину и прячут части маршрута». lessonHref: урок 6.1.
3. **Вода: пруд/ручей/водопад или сухая альтернатива** — why: «Береговая линия только извилистая; исток водопада спрятан; для севера честно рассмотреть карэсансуй — без насосов и гидроизоляции». lessonHref: модуль 3, урок 2.3.
4. **Камни: доминанта участка первой** — why: «Расстановка от главной группы каскадом вниз. Правило Сакутэйки: следуй просьбе камня — форма сама говорит, стоять ему или лежать». lessonHref: уроки 2.1–2.2.
5. **Единая порода камня на весь сад** — why: «Гранит с известняком в одном саду — как два шрифта в одном слове. Для северо-запада ответ готов: местный гранит». lessonHref: урок 2.2.
6. **Заглубление и „направление“ камней** — why: «Минимум на треть в землю; слоистость всех камней группы в одну сторону, как в природном выходе скалы». lessonHref: урок 2.1.
7. **Проверка скелета с видовых точек** — why: «До завоза растений встать (или поставить камеру) в каждую видовую точку: триады читаются? доминанта держит кадр? Сейчас переставить камень — кран на день, потом — перестройка сада».

### Стадия 6 · 植 · Наполнение
**Фаза**: тело сада.
**Intro**: Растения приходят в сад последними и подчиняются камню. Ведомость собирается из «Палитры севера» по ролям: доминанта, каркас, карикоми, акценты, нижний этаж.
**Gate**: посадочная ведомость ≤10 позиций, у каждой позиции — роль и сюжет; план посадок с размерами ям и кронами во взрослом виде.

Пункты:

1. **Дерево-доминанта** — why: «Одно на композицию: сосна в ниваки или лиственница. Место — по главной сцене, формовка со 2–3 года». lessonHref: «Палитра» / доминанты, урок 4.1.
2. **Вечнозелёный каркас** — why: «Половину года сад держат хвойные и зимующие: кулисы, фон водопада, микробиота по склону. На севере эта группа важнее цветущей». lessonHref: «Палитра» / каркас.
3. **Сезонные акценты по календарю** — why: «Клён ложнозибольдов, яблони-«сакуры», дерен на снег — по одному «выступлению» на сезон, привязать к видовым точкам из стадии 3». lessonHref: «Палитра» / акценты, урок 1.1.
4. **Карикоми: группы как камни** — why: «Спирея/кизильник группами 3–5 с доминантой, формы шире к низу; продолжить ритм настоящих камней». lessonHref: урок 4.2.
5. **Мох и нижний этаж** — why: «Мох — в тень (условия: тень, влага, кислая почва), «псевдомох» из очитков — на солнце. Пласты, дождевание 4–6 недель». lessonHref: урок 4.3.
6. **Контроль кансо: ведомость ≤10 позиций** — why: «Длиннее десяти строк — уже коллекция, не сад. 2–3 вида крупными массами (≥20% площади каждый), остальные — единицы». lessonHref: столп 4 + правило палитры.
7. **Проверка взрослых размеров** — why: «Рисовать кроны 10-летнего возраста, не саженцы: клён у дорожки через 8 лет перекроет сцену — или это и был план (миэгакурэ)?»
8. **Зимняя проверка ведомости** — why: «Мысленно убрать всё листопадное: сад в ноябре всё ещё композиция? Если нет — усилить каркас и зимнюю графику (кора, побеги, юкицури)». lessonHref: «Палитра» / вечнозелёный каркас.

### Стадия 7 · 灯 · Детали и свет
**Фаза**: подача.
**Intro**: Детали — то, что заказчик фотографирует, а знаток проверяет первым. У каждого фонаря и камня дорожки есть каноническое место и должность; свет — это несколько тёплых картин в темноте, а не подсветка территории.
**Gate**: план МАФ с привязками + светотехнический план (3–5 акцентов) с прописанной температурой ламп.

Пункты:

1. **Фонари: тип по месту** — why: «Юкими — у воды, орибэ — у цукубая, касуга — парадный. Фонарь освещает что-то конкретное, а не стоит «для красоты»». lessonHref: урок 5.1.
2. **Цукубай / источник звука** — why: «Чаша с капелью или сиси-одоси — звуковой якорь тишины, особенно в замкнутом дворе». lessonHref: урок 5.1, практикум «тенистый двор».
3. **Дорожки: тоби-иси и нобэдан по назначению** — why: «Тоби-иси задают темп (крупный камень = остановка у сцены), нобэдан — парадные и нагруженные участки. Раскладку проверить проходом по месту». lessonHref: урок 5.2.
4. **Секимори-иси и «управление» посетителем** — why: «Куда нельзя — говорит камень с верёвкой, а не табличка. Каждый элемент — с ролью (столп 3)». lessonHref: столп 3.
5. **Световой сценарий: 3–5 акцентов** — why: «Тёплый 2200–2700 К, свет вниз или в объект, источник скрыт, темнота — материал. Больше пяти акцентов — парк аттракционов». lessonHref: урок 5.3.
6. **Ревизия деталей по столпу 3** — why: «Финальный проход: назвать вслух роль каждого фонаря, камня, чаши. Не называется — убрать».

### Стадия 8 · 映 · Визуализация и сдача
**Фаза**: подача.
**Intro**: Проект переводится на язык, понятный заказчику: не чертёж, а картины его будущего сада по сезонам. Здесь работают материалы ваби-саби и жёсткая камера.
**Gate**: комплект: генплан, дендроплан+ведомость, разбивочный/посадочный чертежи, план МАФ и света, альбом визуализаций (мин. 3 сцены × сезоны).
*(Примечание: конкретные шаги в Archicad/Enscape добавим отдельной веткой, когда соберём шаблон Archicad — см. «Дальше».)*

Пункты:

1. **Камеры = паспорт видовых точек** — why: «Каждая камера визуализации — точка из стадии 3, высота 1,5–1,6 м. Никаких «красивых ракурсов с дрона» как основных». lessonHref: урок 1.3 deep-dive, урок 6.1.
2. **Материалы с «налётом времени»** — why: «Камень с лишайником, серебристое дерево, гравий с бороздами: новый чистый гранит убивает картинку». lessonHref: урок 6.2.
3. **Три сезона одной точки** — why: «Весна/осень/зима строго с одного ракурса — заказчик видит календарь любования, а не картинку». lessonHref: урок 6.3.
4. **Ночной тест** — why: «Прогон ночного режима: свет не слепит ни с одной видовой точки, фонарь теплится, а не сияет». lessonHref: урок 5.3 + рекомендации.
5. **Walk-through по маршруту** — why: «Пройти маршрут от первого лица и назвать для каждого поворота: показывает / скрывает / тормозит. Поворот без ответа — лишний». lessonHref: deep-dive урока 1.3.
6. **Комплект документации** — why: «Генплан, дендроплан, разбивочный, посадочный, МАФ+свет, ведомости, альбом. Плюс лист «очередей строительства» из стадии 2».
7. **Финальная проверка шести столпов** — why: «Последний фильтр перед сдачей — тот же, что в начале: каждый элемент объясним? Курс закольцовывается». lessonHref: урок 1.2.

## 5. UI/UX-спецификация

### Страница `/process`
- Заголовок в стиле `ModuleHeader`: кандзи 順, лейбл «Раздел · инструмент», заголовок «От топосъёмки до проекта», intro: суть трекера + фраза о том, что галочки и заметки сохраняются в браузере на этом устройстве.
- Сразу под шапкой — **общий прогресс**: тонкая линия-прогресс в палитре (`--line` фон, `--shu` заполнение), рядом текст «12 / 54 · стадия 3 из 8». Без «геймификации» — сдержанно, в духе сайта.
- Далее — 8 стадий-аккордеонов.

### Стадия (`ProcessStage`)
- Шапка стадии кликабельна (сворачивание): кандзи стадии (`.kj`-стиль, цвет фазы), номер+название (Cormorant Garamond), мини-прогресс «5/9», индикатор +/− как у `.deep`.
- Слева у карточки — 3px полоса цвета фазы.
- Под шапкой (в развёрнутом виде): intro стадии, затем пункты, в конце — блок **«Ворота»** в стиле `.note` (рамка `--shu`): условие перехода к следующей стадии.
- Завершённая стадия (все пункты отмечены): кандзи меняет цвет на `--shu`, к названию добавляется тонкая пометка «済» (завершено) — единственный «праздничный» элемент, никаких конфетти.

### Пункт (`ProcessItem`)
- Строка: кастомный чекбокс (квадрат 18px, рамка `--line`, при отметке — заливка `--shu` и белая галочка; НЕ ромб, чтобы не конфликтовать с буллетами контента) + название пункта.
- Под названием — `why` мелким кеглем `--ink-soft`; в конце строки-why — ссылка на урок (`lessonLabel`) обычным `--pine`-линком.
- Ниже — кнопка-строка «заметка» / текст заметки: если заметка пуста, показывать бледную ссылку «+ заметка»; клик раскрывает textarea (авто-рост, фон `--paper-deep`, рамка `--line`, без резких теней). Если заметка есть — показывать её текст сразу, клик = редактировать.
- Отмеченный пункт: название приглушается до `--stone`, лёгкое зачёркивание НЕ делаем (плохо читается с серифами) — только цвет.

### Поведение
- Все изменения — мгновенно в state, запись в localStorage с debounce 300–500 мс.
- Кнопка «Сбросить прогресс» внизу страницы, с confirm-диалогом; сбрасывает галочки и свёрнутость, **заметки — отдельным вторым вопросом** («Удалить и заметки?»).
- Кнопка «Экспорт в текст»: генерирует markdown (стадии → пункты с [x]/[ ] → заметки) и копирует в буфер — чтобы перенести в мессенджер/документ проекта.
- `prefers-reduced-motion` — уважать (без анимаций аккордеона).
- Доступность: аккордеоны — `<button aria-expanded>`, чекбоксы — настоящие `<input type="checkbox">` со скрытым нативным видом, фокус-обводка `--shu` (уже принято на сайте).

### SSR-нюанс
Компонент читает localStorage → рендерить трекер только после mount (`useEffect` + флаг), до этого — скелет стадий без галочек, чтобы не ловить hydration mismatch.
